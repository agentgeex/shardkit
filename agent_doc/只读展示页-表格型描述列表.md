## 一、它长什么样

四列网格 = `标签 | 值 | 标签 | 值`，整行字段横跨后三列：

```
┌────────┬──────────────────────┬────────┬──────────────────────┐
│ 名称   │ 第 10 章 · 结构化…    │ 执行ID │ run_w_ch10_s01_…     │   ← 半行 ×2
├────────┼──────────────────────┼────────┼──────────────────────┤
│ 状态   │ [运行中]             │ 标签   │ [内容生产][章节写作]  │
├────────┼──────────────────────┴────────┴──────────────────────┤
│ 内容摘要│ 长文本，横跨 3 列，自动换行                            │   ← 整行 span=2
└────────┴─────────────────────────────────────────────────────┘
```

- **标签列固定 150px、浅灰底、加粗**
- **1px 网格线全包，相邻单元格共用一条**（靠 `border-collapse`，不会出双线）
- **空值统一渲染 `-`**，页面不用每处自己判空
- `<768px` 自动降为单列（标签在上、值在下），不出横向滚动条

效果可看：本仓库 `/detail-view` 路由（dev 端口见 `agent_doc/usage-manual.md`）

### 令牌必须新增（不能省）

```css
/* src/index.css */
:root {
  /* 表格/描述列表「标签列」底色。取值须落在「白框底 255」与「网格线 ~232」之间，
     才能同时与两侧拉开 —— 见第五节坑 3。 */
  --table-head: 220 20% 96%;      /* = rgb(243,244,247) */
}
.dark {
  /* 暗色方向相反：网格线比标签更亮，标签要往更暗走，但仍须亮于内容面 */
  --table-head: 240 8% 12.5%;     /* = rgb(29,29,34) */
}
```

```js
// tailwind.config.js → theme.extend.colors
"table-head": "hsl(var(--table-head))",
```

⚠️ 这是**构建期配置**：改完必须重启 dev server 才生效（Vite 不热更 `tailwind.config.js`）。
改前实测会表现为「class 完全没生成、元素无背景」，别误判成代码写错。

## 三、API

```tsx
import { Descriptions, DescriptionsItem } from "@/components/ui/descriptions";

<Descriptions labelWidth={150}>     {/* labelWidth 可省，默认 150 */}
  <DescriptionsItem label="名称">张三</DescriptionsItem>
  <DescriptionsItem label="执行 ID">
    <span className="font-mono text-[13px]">run_abc123</span>
  </DescriptionsItem>
  <DescriptionsItem label="状态"><StatusBadge status="running" /></DescriptionsItem>

  {/* span={2} = 整行，值横跨后三列 */}
  <DescriptionsItem label="内容摘要" span={2}>
    <p className="max-w-prose whitespace-pre-line leading-relaxed">{summary}</p>
  </DescriptionsItem>
</Descriptions>
```

| prop | 类型 | 说明 |
|---|---|---|
| `label` | `ReactNode` | 标签文案（左侧灰底格）|
| `span` | `1 \| 2` | 1 = 半行（默认，两字段并排）· 2 = 整行 |
| `children` | `ReactNode` | 值。**`null / undefined / '' / 纯空白` 一律自动渲染 `-`** |
| `labelWidth` | `number` | 容器级，标签列宽，默认 150 |

值可以是任意 ReactNode：纯文本、等宽 ID、状态徽标、徽标组、日期、数字、长文本块、图片/附件卡片。
页面范例里 8 种都给了样例，照抄即可。

## 四、页面结构（白框模式，本项目规范）

```
ContentFrame（白框）
├── 身份条（框内首行，data-testid="detail-head"）
│     图标 + 实体名(h1) + 等宽 ID + 状态徽标 + 角色徽标 ｜ 右侧：编辑 / 返回
│     底部 border-b 分隔，mb-4 pb-4
├── 分区 1「基础信息」  ← h2 + <Descriptions>
├── 分区 2「内容」      ← h2 + <Descriptions>
└── 分区 3「附件与元数据」← h2 + <Descriptions>
```

三条规矩：
1. **框内不再叠卡片** —— 分区之间用横线（本项目 `ContentFrameSection`），不用 `Card`
2. **没有页头大标题** —— 导航已高亮页名；框内首行那个 h1 是「实体身份」，不是页头
3. **返回按钮永远在最右**，编辑在其左

## 五、五条硬规则（每条都是踩出来的，带实测数字）

### 坑 1｜整行项必须后置，否则同页多张表会错位
`table-fixed` 的列宽**由首行的单元格数决定**。
若某张表首行就是 `span={2}`（2 格），该表会被定成 2 列，后续 4 格行的余宽被三等分：

```
首行 4 格： [253.5, 403.5, 824.0, 974.0]   ✅
首行 2 格： [253.5, 403.5, 733.8, 1064.2]  ❌ 右半列漂移 90px
```

**基元已强制「span≥2 的整行项一律后置」**（稳定分区，同 span 组内保持书写顺序），
所以页面无需自觉维持顺序。代价：将来若真需要整行块打头，得另加开关 prop，目前刻意不留后门。

### 坑 2｜禁用 `<colgroup>` / `<col>` 定列宽
`<col>` 的列宽优先级**高于** `max-md:w-full`，手机端标签格会卡死在 150px 的小灰块。
所以列宽只写在 `th` 的 class 上；只有自定义 `labelWidth` 时才用内联 `style`。

### 坑 3｜标签底色是「三方挤压」，只验一边必翻车
标签底夹在「白框底」和「网格线」之间，必须落在**两者中点附近**：

| | 标签底 | 网格线 | 白框底 | 底vs线 | 底vs框 |
|---|---|---|---|---|---|
| ❌ 错（93%）| `rgb(234,236,240)` | `rgb(229,231,235)` | 255 | **5.0** 线被吃掉 | 18.3 |
| ✅ 对（96%）| `rgb(243,244,247)` | `rgb(229,231,235)` | 255 | **13.0** | 10.3 |
| ✅ 暗色（12.5%）| `rgb(29,29,34)` | `rgb(39,39,43)` | 22.3 | **9.7** | 8.3 |

> **第一次做的版本只验了「底 vs 框」（18.3，看起来很够），结果线只剩 5 个色阶，1px 的框直接消失。**
> 要求：改这两个值必须**同时**验 `|底−线|` 与 `|底−框|`，两边都要够。
> **暗色方向相反**：暗色下网格线比标签更亮，标签要往更暗走，但仍须亮于内容面。

### 坑 4｜空值用常规前景色，不要用 muted
褪色的短横线在白底上会被目视读成「这格漏了内容」（AI 目视也误判过）。
所以 `-` 用 `text-foreground`，靠「它只是个短横线」来表达空，不靠褪色。

### 坑 5｜真 `<table>` + `border-collapse`，不要用 grid
「网格线全包、相邻单元格共用一条 1px」只有 `border-collapse` 能做到；
grid + 逐格 border 会出双线，靠负 margin 补又会在换行/缩放时露出 2px。

## 六、验收清单（可直接照跑）

| # | 断言 | 期望 |
|---|---|---|
| 1 | `document.querySelectorAll('input,select,textarea').length` | **0** ← 这是"只读"的硬证据，光看截图不算 |
| 2 | 三张表每个 4 格行的单元格 x | 完全一致（本项目为 `253.5 / 403.5 / 824 / 974`）|
| 3 | 标签列 `getComputedStyle().backgroundColor` | ≠ 白色；宽 150±2 |
| 4 | 标签字重 | ≥600 |
| 5 | 单行行高 | 44–48px |
| 6 | 空值格文本 | `-` |
| 7 | 整行项值宽 | ≈ 半行项的 2 倍以上（本项目 991 vs 420.5）|
| 8 | 1440 / 768 / 375 | `scrollWidth <= clientWidth`（无横向滚动）|
| 9 | 375 上标签格 | `display: block`，宽 = 表宽 |
| 10 | light / dark 两主题 | 上面坑 3 的两个差都达标 |
| 11 | 全程 | 0 pageerror |

> 第 1 条最容易被跳过：**「不可编辑」要能量出来，不能靠"我没写 input"自证。**

## 七、已知局限（用之前先知道）

1. **整行项后置不可由页面覆盖** —— 基元强制。需要打头时再加开关 prop。
2. **无分页 / 无排序 / 无折叠** —— 纯展示基元，不做交互。（参考实现 Element Plus 的 `Descriptions` 有折叠头，本项目刻意不做：折叠会让人以为内容缺失）
3. **附件为「令牌渐变缩略块 + 图标 + 文件名」，不是真图片预览** —— 避免外链图破图/离线失效。要真图需自备素材。
4. **只服务单对象展示** —— 列表/多记录请用 `Table`，两者语义不同。

## 九、一句话总结

**一个只读页的体面，全在「标签列」上**：
它得有底色撑出层次、但底色不能被网格线吃掉；得固定宽度撑出网格、但不能写死到手机里；
得让整行字段跨满、但不能把列数带跑。

这三个都是数值问题，不是审美问题 —— 所以本文全给了实测数字，照抄不会错。
