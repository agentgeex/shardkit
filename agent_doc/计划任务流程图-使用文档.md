## 1. 这是什么

**计划任务流程图** 把 AgentOS 的「计划（plan）」渲染成一张**从左到右的流水线式 DAG**，并支持**演示播放**，用于：

- 直观查看一个计划由哪些步骤（step）组成、步骤之间的依赖关系；
- 观看执行过程：当前执行到哪一步、已走过哪些路径、路径如何流转；
- **大屏演示**：自动播放 + 镜头自动追踪当前执行框，画面"跟着跑"。

技术选型背景见 `agent_doc/计划任务流程图-技术选型与实现方案.md`。

## 4. 数据源与数据契约

本组件支持**两种数据源**，通过适配器转换为统一的 React Flow 结构。

### 4.1 A. 真实导出（推荐）

数据来自 AgentOS 的 plan 导出工具产物（示例目录：
`~/.agentos/openclaw_agents/agentgeex_agent/workspace/plan_exports/`）：

| 文件 | 用途 |
|------|------|
| `*.graph.json` | 拓扑图（nodes + edges），渲染主数据 |
| `*.steps_json.json` | 步骤指令全文（填充详情面板的 instruction） |

**graph.json schema：**

```jsonc
{
  "plan_id": "plan_119dfdc4ce44",
  "project_id": "proj_db47457ce25d",
  "activate_mode": "...", "mode": "full", "chapter": "ch10",
  "n_top_steps": 6, "n_nodes_expanded": 137,
  "nodes": [
    {
      "run_uuid": "run_quality_write_ch10_119dfd",
      "task_id": "task_0e9b2b685cb4",
      "agent_id": "book_writer_0ab73b",
      "plan_section": "...", "depth": 1,
      "parent_run_uuid": "...",        // 与 prev_task 互斥
      "prev_task": null, "next_task": "run_review_r1_entry_ch10_119dfd",
      "children": ["run_w_ch10_s01_119dfd", "..."], "n_children": 12
    }
  ],
  "edges": [
    { "from": "A", "to": "B", "type": "children" },  // 结构边
    { "from": "B", "to": "C", "type": "next" },      // 时序边
    { "from": "C", "to": "B", "type": "prev" }        // 时序边(反向)
  ]
}
```

**edge 三种类型：**
- `children` —— 父→子（**结构/包含**，实线）；
- `next` —— 前置→后置（**时序**，虚线）；
- `prev` —— 后置→前置（时序反向，渲染时通常跳过，避免回环）。

> ⚠️ **关键限制**：导出 **不含 `run_status`**（运行态字段）。本组件在无状态时用**拓扑序推断一个"演示态"**，并在 UI 明确标注（左上角黄字）。**真实运行态需另接 `ao_task_execution.run_status`** 覆盖（见 §6 接入指引）。

### 4.2 B. 内置演示（mock）

`src/pages/cases/plan-flow/mock.ts` —— 严格对齐 `docs/PROJECT_MANAGEMENT.md §3.2` 的 plan schema，
覆盖 §3.5 全部六种拓扑，用于离线演示与回归。

```ts
interface PlanStep {
  run_uuid: string; task_id?: string; agent_id: string;
  instruction: string;
  parent_run_uuid?: string | null;   // 与 prev_task 互斥
  children?: string[]; prev_task?: string; next_task?: string;
  timeout_seconds?: number; scheduled_at?: string;
  status?: RunStatus;   // 真实来源：ao_task_execution.run_status
  label?: string; duration_seconds?: number;
}
```

### 4.3 适配器文件

| 文件 | 职责 |
|------|------|
| `export-adapter.ts` | 真实导出 `graph.json` → React Flow（**阶段列布局** + 状态推断 + 标签中文化） |
| `adapter.ts` | mock `Plan` → React Flow（**dagre 自动布局**）；同时导出 `StepNodeData`、`STATUS_COLOR` |
| `playback.ts` | 演示播放器：执行顺序计算 + 播放状态 + 节点/边着色 |
| `step-node.tsx` | 自定义节点 `StepNode`（步骤卡：名称/Agent/run_uuid/状态/高亮） |

## 5. 布局算法

### 5.1 真实导出：主链分列 + 子任务下挂（`export-adapter.ts`）

> 2026-10-27 重写。旧版「按阶段名列」有三处硬伤，见 §5.4。

布局原则是**把两类关系在空间上正交化**：

| 关系 | 数据字段 | 走法 |
|---|---|---|
| 时序（先后） | `next_task` / `prev_task` | **横向向右**，主链恒在 `y = 0` 一行 |
| 结构（包含） | `children` / `parent_run_uuid` | **纵向向下**，子任务挂父节点右侧一列 |

具体算法（`layoutByChain`）：

1. 从「既无 `prev_task` 又无 `parent_run_uuid`」的根出发，沿 `next_task` 走出**主链**
   （书籍管线 = 17 步主干）；
2. 主链上每个节点占一列，`x` 累加；有子节点的父占 660px（父 240 + 子列 300 + 留白），
   无子的占 320px；
3. 该父的 `children` 排在同一列下方，`y = 132 × k`；
4. 孤立节点（环 / 数据不一致）兜底排到最后一段。

**为什么不用 dagre？** 实测 137 步：
- 只喂 `children` 边 → 被排成 `H≈15232px` 的**竖线**（不可读）；
- 喂全部边 → 形状可读但**对角线漂移**，列不对齐。

### 5.2 内置演示：dagre 自动布局（`adapter.ts`）

`rankdir=LR, nodesep=60, ranksep=140`，节点 `240×92`。

### 5.3 间距参数

| 参数 | 位置 | 值 | 含义 |
|------|------|----|------|
| `CHILD_DX` | export-adapter | `300` | 父 → 子列横向偏移（太小会让 12 条父子边重合） |
| `ROW_GAP` | export-adapter | `132` | 列内纵向间距（父 92 + 净空 40） |
| `NODE_W / CHILD_W / NODE_H` | export-adapter | `240 / 200 / 92` | 父卡 / 子卡 / 高 |
| 蛇形分行 | plan-flow.tsx | `5 个/行`、行距 `160` | 仅「全部折叠」时启用 |

### 5.4 旧版为什么错（2026-10-27 修复记录）

| # | 缺陷 | 实测后果 |
|---|---|---|
| 1 | 阶段名表漏了「审校入口 / 试读入口 / 修订入口」→ `indexOf` 返回 -1 → 排序当 99 | 父节点被甩到图最右端，距其子 **2580px**，父子边**从右往左画** |
| 2 | R1/R2/R3 三轮同阶段名压进同一列 | 36 个节点垂直堆叠 **4608px** |
| 3 | 父子边复用时序边的 `--border`（与画布同色） | 对比度 **1.22:1**，肉眼看不见；时序虚线却是 7.11:1 —— 明暗倒挂 |
| 4 | 播放器 `applyPlayback` 写死 `strokeDasharray: undefined` | 把虚线硬改成实线，两类边在播放态彻底同化 |

修复后实测：父子边跨度 **2828px → 300px**；跨 ≥2 列长边 **108 条 → 0 条**；
父子边对比度 **1.22:1 → 3.34:1**；方向由「←」变「→」。

## 6. 四大可视化能力（含实现要点）

### 6.1 当前执行节点高亮

- 触发：`playback` 给出 `current` 节点 id；
- 呈现：**红色 3px 描边 + 外发光 + 呼吸动画 + 放大**，状态文案改"执行中…"；
- 与"已完成=绿"明确区分。

### 6.2 路径线染色

`applyPlayback()` 统一着色：

| 状态 | 颜色 | 样式 |
|------|------|------|
| 当前正在走 | 🔴 红 | 实线 3.5px + 流动动画 |
| 已走过 | 🟢 绿 | 实线 2.5px |
| 未走 | ⚪ 灰 | 原样式 |

> **父子边（`data.kind === "struct"`）不参与染色** —— 它表达的是归属，不是执行先后，
> 不该因为"走过了"而变绿。染色时会保留原 `strokeDasharray`（旧版写死 `undefined`，把虚线改成实线）。

### 6.3 点击节点弹详情

`onNodeClick` → `Dialog`，展示：执行 Agent / 状态 / task_id / 超时 /
**instruction 全文** / prev_task / next_task / children。

### 6.4 当前执行内容浮层 + 自动追踪

- **浮层位置**：画布**左下角**（2026-10-27 从左上移下来，避免压住主干与父节点）；
- **内容**：`正在执行 k/N` + 步骤名 + run_uuid + instruction 摘要；
- **自动追踪**：开关开启时，每步把当前框**平滑居中**（`setViewport` duration 500ms），
  即"镜头跟当前框跑"，适用于大屏自动展示。

### 6.5 演示播放器（`playback.ts`）

- 执行顺序 = **拓扑序**（BFS：从入度 0 出发，children 优先，再沿 next 串行）；
- 状态：`current`（唯一）、`done`（集合）、`activeEdges` / `flowedEdges`；
- 控制：播放/暂停/重置/单步/速度（默认 **3000ms**，范围 0.5–6s）/自动追踪/全部折叠。
- **折叠不会重置播放进度**：`usePlayback` 用 `resetKey`（= 数据源 + 节点数）判断"是否换图"，
  只有换图才回零。否则用户每折一下就丢进度。

### 6.6 父子层级与折叠（2026-10-27 第二档）

#### 两级卡片视觉

| | 父任务（容器） | 子任务（从属） |
|---|---|---|
| 宽度 | `240px` | `200px` |
| 描边 | `2px` `border-foreground/25` | `1px` `border-border` |
| 底色 | `bg-card` | `bg-background`（下沉一档） |
| 标题 | `text-sm font-semibold` | `text-[13px] font-medium` |
| 左侧色条 | `3px` 主色（强锚点） | `2px` 淡灰 |
| 徽标 | 右上角 `N 子`（可点） | 无 |

#### 父子边 = 树状总线

用 `smoothstep` + `pathOptions{borderRadius:10, offset:16}`：
12 条边共用父节点下方一段**竖直干线**，再各自横向分叉到子节点左侧 ——
标准 `└─` 树形走线。比直斜线（扇形）更能一眼看出"这些都归它"。

> ⚠️ 踩过的坑：第一版把子节点放在父节点**正下方 40px**，12 条边几乎垂直重合，
> 视觉上被误读成「节1 → 节2 → 节3」的**串行链**（其实它们是并行兄弟）。
> 现在子列偏移 300px，边不会共线。

#### 折叠（默认全部展开）

- **入口**：父卡右上角 `N 子` 徽标即开关（`nodrag`，不触发拖动）；
- **工具栏**：`全部折叠 / 全部展开` 一键切换；
- **默认状态**：空集合 = 全展开（业务要求）；
- **折叠行为**：隐藏整棵子树（递归，含孙代），统计区显示「已折叠 N 步」；
- **折叠重排**：折叠的父不再占子列宽度，主干自动收紧；
- **全部折叠时**：改用**蛇形分行**（5 个/行、行距 160），保证 17 步主干在一屏内
  仍然可读（实测 `zoom≈0.85`、节点屏幕宽 `≈205px`）。否则按原布局一条线铺开是 8120px，
  fitView 后节点会被压成 20px 小方块。

#### hover 追踪

鼠标停在任一节点 → 直连边变主色高亮、对端节点保留，其余压到 8%/22% 不透明度。
密集图里 12 条父子边互相交叠时，这是定位"这条线连的是谁"的唯一实用手段。

#### 回归测试

```bash
node scripts/verify_plan_flow.mjs     # 12 条断言，末行 ALL PASS
```

覆盖：默认展开 137 节点 / 10 个父徽标 / 父子卡宽 240 与 200 / 单父折叠 137→125 /
工具栏出现「全部展开」/ 统计区「已折叠 N 步」/ 单父展开回 137 / 全部折叠 = 17 节点 /
折叠后边数只余时序边 / 全部展开回 137。

## 10. 常见问题

| 问题 | 原因 / 解决 |
|------|-------------|
| 大图看起来是一根竖线 | 用了 dagre + 只喂 children。改用阶段列布局（已内置） |
| 改了代码页面没变 | vite 监听假死 → 重启 vite（见 §7） |
| 状态色全是推断的 | 导出不含 run_status，属预期；接入见 §8 |
| 137 步标签太小 | 大图默认 0.6 缩放；滚动/缩放查看，或用自动追踪 |
| 想换包名 `reactflow` | ❌ 不行，本组件用 `@xyflow/react` v12，API 不兼容 |
