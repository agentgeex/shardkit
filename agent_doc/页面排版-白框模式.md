# 页面排版模式：去页头 + 白框内容区

> 来源：`note_d8e31b07502a`（agx_ui_lead，2026-10-28 定稿，源自 webtools/client 全站 24 页改版）
> 采纳：win_ui_lead 2026-10-28 全量落地到 shard-kit｜验收脚本 `scripts/verify_content_frame_20261028.mjs`
> 适用：Refine + Tailwind + shadcn/ui 的中后台（无 Refine 也可，令牌对齐即可）

---

## 一、三条规则

| # | 规则 | 一句话 |
|---|---|---|
| ① | **列表页去掉页头标题** | 左侧导航已高亮页名，页面里再写一遍是冗余 |
| ② | **内容装进白框** | 灰画布上浮起一块白卡，工具栏 / 表格 / 卡片群 / 图表全在框内 |
| ③ | **详情页保留页头** | 它不是重复导航，而是**实体身份**（名字 / 状态 / 返回） |

归纳：

> **导航说明「这是哪一页」，白框说明「内容在哪」，页头只留给「这是哪一个具体对象」。**

```
改前                              改后
算力主机            ← h1 冗余      ┌─ 灰画布 ────────────────────────┐
按主机统计占用      ← 说明         │  ┌─ 白框 ────────────────────┐  │
────────────                       │  │ [筛选]        [视图切换]  │  │
[查询条件]                         │  │ ───────────────────────── │  │
[表格]           ← 靠间距分层      │  │ [表格 / 卡片群 / 图表]    │  │
                                   │  └───────────────────────────┘  │
                                   └─────────────────────────────────┘
```

## 二、用哪个组件

| 场景 | 写法 |
|---|---|
| 列表页（无页头） | `<ContentFrame>` + 顶部工具行 |
| 详情页（保留页头） | `<PageHeader layout="inline">` + `<ContentFrame padding={5}>` + `ContentFrameSection` |
| 工作区撑满型（流程图 / 页内滚动） | `<ContentFrame fill>`（自动带 `min-h-0`） |
| 存量未迁移页面 | `<PageHeader layout="stacked">`（旧外观，逐页迁移即可） |

```tsx
// 列表页
export default function ListPage() {
  return (
    <div data-testid="list-case">
      <ContentFrame>
        {/* 工具行：筛选…最右是原页头的动作 */}
        <div className="mb-4 flex flex-wrap items-center gap-2">
          <Input className="flex-1" placeholder="搜索…" />
          <Badge variant="secondary" className="ml-auto font-normal">共 {total} 条</Badge>
          <Button variant="secondary" size="sm">导出</Button>
          <Button size="sm">新建</Button>
        </div>
        <Table>…</Table>
      </ContentFrame>
    </div>
  );
}

// 详情页
<PageHeader
  title="产品详情"
  description={`只读查看 ${product.id}`}
  actions={<>
    <Button variant="edit" size="sm">编辑</Button>
    <Button variant="back" size="sm">返回</Button>   {/* 返回永远是最后一个 */}
  </>}
/>
<ContentFrame padding={5}>
  <ContentFrameSection>…身份行…</ContentFrameSection>
  <ContentFrameSection>…字段区…</ContentFrameSection>
</ContentFrame>
```

页面外层容器：`flex flex-col gap-2`（页头 → 白框 8px）。列表页无页头时用 `flex flex-col`，**不要额外 gap**。

## 三、白框规格（`ContentFrame`）

| 属性 | 值 | 为什么 |
|---|---|---|
| `rounded-xl` | 12px | 大块面用 `rounded-lg`（8px）显生硬 |
| `border-strong/70` | 深一档 | 普通 `border` 在白底 + 阴影下几乎看不见 |
| `bg-card` | 令牌 | **禁 `bg-white`** —— 暗色主题会白到刺眼 |
| `p-4` / `p-5` | 16 / 20px | 列表页 / 详情页 |
| `shadow-sm` | 极轻 | 只做"浮起"暗示；`shadow-lg` 廉价 |
| `data-testid="content-frame"` | 固定 | **跨项目验收探针**，移植时保留原名 |

**四条禁忌**

1. **不要加 `overflow-hidden`** —— 会裁掉 sticky 表头与下拉菜单；
2. **分区不要再用卡片** —— 上下排列的功能段用 `ContentFrameSection` 的 `border-b`（最后一块 `last:border-b-0`），否则「框中框」；
3. **`fill` 模式必须有 `min-h-0`** —— 否则 flex 子项不肯收缩，内部 `overflow-y-auto` 会塌掉；
4. **框内的内容单元卡片必须降噪** —— 见下节，否则白卡叠白卡。

### 3.1 框内内容单元怎么放（本项目补充，原规范未覆盖）

规范原文只区分「列表页 / 详情页」。落地全站时遇到第三类：**一页里有多块并列的内容**
（仪表盘 KPI 卡、案例索引卡片墙、区块画廊、瀑布流图、菜单双栏）。这类块删掉卡片会散架，
保留原样又会「白卡套白卡」。

**本项目定法**：内容单元**保留 `Card`**，但由一条全局 CSS 降噪——只在白框内生效：

```css
/* src/index.css */
[data-testid="content-frame"] [data-card] {
  box-shadow: none;                                  /* 白框已"浮起"，框内不再叠阴影 */
  background-color: hsl(var(--muted) / 0.5);         /* 白 → 浅灰块，层次变"白框 > 浅块" */
  border-color: hsl(var(--border));
}
```

`Card` 组件上打了 `data-card` 标记（`src/components/ui/card.tsx`），所以这是一处改、全站生效。

层次因此变成四级递进：**深色侧栏 → 灰画布 → 白框 → 浅灰内容块**，
不再有"白卡里套白卡"的双层阴影。

> 判据：**上下排列的功能段 → 横线分区；并列的内容单元 → 降噪卡片。**

## 四、⚠️ 去页头 ≠ 删页头里的东西

这是**最容易翻车的一步**。页头内的按钮（视图切换 / 新建 / 统计计数）必须搬到内容区顶部工具行**最右侧**，否则功能凭空消失。

本项目落地时的具体搬运：

| 页面 | 原页头动作 | 搬到哪里 |
|---|---|---|
| `/list` 弹窗式 CRUD | 切到页面式 CRUD / 导出 / 新建产品 | 工具行「共 N 条」之后 |
| `/list-page` 页面式 CRUD | 切到弹窗式 CRUD / 导出 / 页面式新建 | 同上 |

## 五、页头（`PageHeader`）

`layout` 两档，**默认 `inline`**（新写法）：

```tsx
<div className="mb-0 flex flex-wrap items-end gap-x-3 gap-y-1">
  <h1 className="text-xl font-semibold tracking-tight">{title}</h1>
  <p className="text-sm text-muted-foreground">{description}</p>
  <div className="ml-auto flex items-center gap-2">{actions}</div>
</div>
```

实测调出来的数，别改：

| 项 | 值 | 说明 |
|---|---|---|
| `items-end` | 底对齐 | 20px 标题与 14px 说明底对齐；少了它说明会"飘"在中间 |
| `gap-x-3` | 12px | **说明紧跟标题右侧**。曾 `justify-between` 推到最右 → 被否：「放右边就没效果了」 |
| 说明字号 | `text-sm` | 14px 不变，不为配合标题缩小 |
| `mb-0` | 0 | 间距交给页面容器 `gap-2` |
| `actions` | `ml-auto` | 靠右，与内容右边界对齐 |

> `layout="stacked"` 只为存量页面保留，新页面不要用。

## 六、按钮按用途分色

白底上 `ghost` / `outline` 描边按钮**基本看不见**（对向项目返工三次）→ **可见按钮一律实底 + 白字，靠色相区分用途**。

| variant | 色 | 用途 | 令牌 |
|---|---|---|---|
| `default` | 蓝 | 新建 / 保存 / 确认 / 提交 | `--primary` |
| `run` | 绿 | 运行 / 重跑 / 重试 | `--action-run` |
| `view` | 青 | 详情 / 打开 / 流程图 | `--action-view` |
| `edit` | 橙 | 编辑 / 修改 / 配置 | `--warning` |
| `back` | 紫 | 返回 / 后退 | `--action-back` |
| `destructive` | 红 | 删除 / 归档 | `--destructive` |
| `secondary` | 灰 | 取消 / 关闭 / 重置 / 页间跳转 | `--secondary` |

**实测对比度**（亮色，`verify_content_frame_20261028.mjs`）：

| 按钮 | 底色 | 对比度 |
|---|---|---|
| 新建（蓝） | `rgb(80,72,229)` | **6.18:1** |
| 详情（青） | `rgb(4,112,139)` | **5.68:1** |
| 编辑（橙） | `rgb(245,159,10)` | **6.87:1** |
| 返回（紫） | `rgb(99,47,188)` | **7.88:1** |
| 删除（红） | `rgb(239,68,68)` | 3.76:1 |

硬约束：按钮 ≥3:1、正文 ≥4.5:1，**必须实测**，不能靠"这是语义色"推定。

> 命名取舍：切到另一套案例属于**页间跳转**，用 `secondary` 灰，不要占用 `view` 青
> —— 青色留给真正的「详情 / 打开」。同一页里颜色语义一旦复用，就没人记得住。

探针写法（只读，不点业务动作）：

```js
const f = document.querySelector('[data-testid="content-frame"]');
const cs = getComputedStyle(f);
const fr = f.getBoundingClientRect();
// 期望：bg rgb(255,255,255)（亮）/ --card 暗档（暗）；radius 12；border 1；padding 16|20
// 期望：x≥200 && y≥90 && w>1000（白框与画布有间距）
```

每页必查 5 项：① 白框 `bg/r/b/p` 合规；② 内容几何在框内；③ 列表页无标题、详情页有标题 + 返回；
④ 白框与画布有间距；⑤ 0 个 `pageerror`。

纪律：**只点 tab / 刷新、数卡片；不点运行、不提交业务表单**；期望值现算，不二次硬编码。

> ⚠️ shard-kit 默认主题是 **dark**（`index.html` 预置）。验白框必须显式把
> `localStorage["shardkit.theme"]` 设成 `light`，否则量到的是 `--card` 暗档（`#15151A`），
> 会误判成"白框没生效"。暗色另跑一组：只要「不是写死白色」且「比画布亮」即通过。

## 八、踩坑清单

1. **`items-end` 不能省** —— 少了它，"底对齐"变"中间对齐"。
2. **说明不能推到最右** —— 必须紧跟标题 12px。
3. **去页头时按钮要搬家** —— 否则功能消失（见 §4）。
4. **白框里不要再用卡片** —— 用 `ContentFrameSection` 横线分区。
5. **`fill` 模式漏 `min-h-0`** —— 工作区被撑开、滚动条消失。
6. **改 `PageHeader` 默认值会波及存量页** —— `stacked` → `inline` 后所有未显式传参的页面视觉都变；
   本项目做法：未迁移页面**显式传 `layout="stacked"`**，逐页迁移，不搞一次性大爆炸。
7. **改 tsx 后清 Vite 缓存** —— `rm -rf node_modules/.vite` + 重启；提示用户 **Cmd+Shift+R**。
8. **`content-frame` 不要加 `overflow-hidden`** —— 裁 sticky 表头与下拉菜单。
9. **`data-testid="content-frame"` 是探针** —— 移植时保留原名。
10. **默认暗色主题会让"白框"验成黑框** —— 见 §7 的说明。
11. **探针 `data-testid` 会被调用方覆盖** —— `ContentFrame` 内部把它写在 `{...props}` **之后**，
    保证永远是 `content-frame`，脚本不会因为有人传了自定义 testid 就漏检。
12. **一页只能一个白框** —— 两个并列的白框看起来像"两页拼一起"，并列内容放同一个框里用横线分区。
13. **"白框 + 内部还是卡片堆"= 没改**（2026-10-28 维护者反馈）—— 只在外层套一个白框、内部仍保留 3 张卡，
    肉眼看不出变化。白框内必须**真按横线分区重组**：详情页的「配置 / 指标 / 时间线 / 详情标签页」
    逐个变成 `ContentFrameSection`，指标小卡去掉边框改字段式。
14. **画布页给画布加底色 = 白框消失**（计划流程图，**结论改过一次**）——
    先试过「`p-2` + 浅灰内嵌画布区」，但内嵌区用 `--background` 后画布色 = 页面色，
    白框下半截直接与页面融为一体。正确做法见 §10.2：**框内零内距，画布区不给任何底色**，
    整块留 `--card` 白，靠点阵网格 + 上面的 `border-strong` 横线分区。
15. **页头也可以"降级"而不是二选一** —— 详情/表单页除了"保留 inline 页头"和"完全去掉"，
    还有第三种：把页头降为**框内首行身份条**（左边标题+ID+状态，右边动作，下方一条横线）。
    这种既去掉了页头占位，又不丢"这是哪个对象"和操作按钮。
16. **`border-border-strong` 是个不存在的类名**（2026-10-28 发现）—— `tailwind.config.js` 里写作
    `borderColor.strong`，所以类名是 **`border-strong`**。写错的类名不会报错，会静默回退成 Tailwind
    默认边框色 `#E5E7EB`，比设计值 `#D0D5DF` 还浅 → **全站白框描边一直偏淡**。已全量纠正。
17. **`shadow-sm`（0.05）在浅灰底上等于没有** —— 白框用 `shadow-surface`；描边用满强度
    `border-strong`（原来 `border-strong/70` 一叠透明度又淡一截）。
18. **判断「白框是否成立」不能只看脚本** —— 24 路由扫描全 PASS 时，`/plan-flow` 的画布其实
    跟页面同色、白框下半截根本不存在。脚本验证的是「规格」，不是「看起来有没有」。

## 十、画布页（`/plan-flow` 这类）

画布页最容易被做成「工具条 + 一块画布」两段式，看起来跟其它页不是一个体系。四条铁律：

### 10.1 整页只能有一个白框，工具栏必须在框内

```tsx
<ContentFrame fill padding={0}>          {/* padding=0 档：框内零内距，内容自己管 */}
  <div className="flex flex-col gap-2 border-b border-strong p-3">   {/* 工具栏 = 框内第一分区 */}
    …
  </div>
  <div className="relative min-h-0 flex-1 overflow-hidden">           {/* 画布 = 框内第二分区 */}
    <ReactFlow … />
  </div>
</ContentFrame>
```

工具栏留在框外 → 页面变成「一条工具栏 + 一块画布」，白框只包住画布，与其它页不是一套。
`ContentFrame` 的 `padding=0 && fill` 会自动补 `gap-0 overflow-hidden`（画布页要贴边 + 裁圆角）。

### 10.2 画布**不要给底色**

画布区一旦用 `--background` / `bg-muted/xx`，就是给白框挖了个洞：白框下半截与页面融为一体，
四边只剩工具栏那一条白边，白框等于不存在。**整块都留 `--card` 白**，靠点阵网格 + 上面的横线分区。

### 10.3 分区横线用 `border-strong`，不要用 `border-border`

`--border`（#E2E5EC）在白底上几乎不可见，`--border-strong`（#D0D5DF）才看得出来。

### 10.4 浮层（Panel）要收，不要摊

- 图例、统计这类**静态信息**并进左上信息卡，别单独浮一条（否则四个角全是浮层，画布像补丁）；
- 小地图 ≤ 160×110；
- 「当前执行」卡收窄到 264px 以内。

### 10.5 大图默认折叠，别默认全展开

137 步全展开时节点被压到字号不可读、整屏密不透风。**节点数 > 60 时按数据源自动折叠到阶段级**
（137 → 17 个容器卡，一眼看清主干），用户点「全部展开」再展开。

### 10.6 默认不要自动播放

自动播放每步都把视口居中到当前节点，刚 `fitView` 好的全局视图立刻被拽走 ——
**页面永远构图不定**，怎么调都觉得乱。进来先给一张稳定的全局图，要看演示自己点「播放」。

### 10.7 `fitView` 必须等节点量完尺寸

折叠 / 换行会整体换一批节点，提前 fit 用的是换行前的 bbox → 内容被顶到画布下半部、右边大片留白。
用 `useNodesInitialized()` 卡住：

```tsx
const nodesInitialized = useNodesInitialized();
React.useEffect(() => {
  if (!nodesInitialized) return;
  const t = setTimeout(() => fitView({ padding: 0.12, duration: 300 }), 60);
  return () => clearTimeout(t);
}, [nodesInitialized, baseNodes.length, hidden.size, fs]);
```

### 10.8 React Flow 的写死浅色要接管

React Flow 自带一组写死的浅色（controls 按钮 `#fefefe`、attribution `rgba(255,255,255,.5)`、
小地图节点 `#e2e2e2`），暗色下直接露出白块。在 `index.css` 里统一用它的 CSS 变量接管，
不要在各页面打 `!bg-*` 补丁：

```css
.react-flow {
  --xy-controls-button-background-color: hsl(var(--card));
  --xy-controls-button-color: hsl(var(--foreground));
  --xy-controls-button-border-color: hsl(var(--border));
  --xy-minimap-background-color: hsl(var(--card));
  --xy-minimap-node-background-color: hsl(var(--muted-foreground) / 0.5);
  --xy-attribution-background-color: hsl(var(--card) / 0.8);
  --xy-background-pattern-color: hsl(var(--border));
}
```

### 10.9 大图（>60 节点）展开态：画布**没有滚动**，只能靠 pan / zoom / 分组

**实测（2026-10-29，1440×900，书籍创作 137 步）**：

- 全图 1:1 约 **8760×1675**，画布只有 **1182×622**；
- 要「全见」需 zoom≈**0.135**（实测点 fitView 得 0.1228），此时 14px 父标题的有效字号只有 **1.72px**；
- 要「可读」（14px → 有效 ≥10px）需 zoom≥**0.71**（0.8 时有效 11.2px），但一屏只覆盖全图约 **1/10**。

→ 结论：**137 个节点不可能既全见又可读**，这是面积决定的，不是调参能解决的。

所以展开态必须给「可读落点」，并且把「看局部」变成可见事实：

| 必须做 | 做法 |
|---|---|
| 落点可读 | 展开后定位到**第一列入口**、zoom≈0.8；不要钉死一个任意 zoom（旧实现钉 0.45，137 个里只露出 32 个、框外 109 个） |
| 尺度可见 | 工具栏常显「已展开 N · 当前视野 M · 缩放 x%」，数值现算 |
| 全局可达 | 单独给「适配全图」按钮（接受 0.12 → 仅看结构），**不要**把它做成默认落点 |
| 分组导航 | 按主链列给「阶段聚焦」徽标（写作 / 审校 R1 / …），点一下把 137 变成 12 可读 |
| 浮层收敛 | 展开态信息卡收成一行徽标、小地图默认收起（开关唤出）、载荷卡只在播放/悬停时挂载 |
| 不要给画布加滚动 | `overflow:hidden` 是对的（页面 `scrollHeight == clientHeight`）；用户直觉的「往下滚」不成立时，用 pan / zoom / 聚焦替代，并在 UI 上说明 |

验收不能只看「白框规格」：`verify_content_frame` 全 PASS 时，展开态仍可能只露出 32/137。必须**同时**断言几何（zoom ≥0.7、入口节点在画布内、浮层与节点相交数 = 0）+ 人工看图。

## 十二、导航栏刷新按钮（shard-kit 落地，2026-10-28）

> 规范来源：`note_cf70980bb4ed` / agentos `webtools/client/agent_doc/2026-10-28-页面排版规范-白框模式与刷新按钮.md` 第八章。
> 这一段跟白框无关，但同一批交付，且是「中后台最常见的抱怨」的解药。

### 12.1 解决什么问题

| 坑 | 现象 | 根因 |
|---|---|---|
| ① 「刷新」只在右键菜单里 | 用户不知道能刷新 | 交互路径太长 |
| ② `navigate(当前路由)` 刷新无效 | 点了数据没变 | **同路由 navigate 不重挂**，React 复用组件实例，不重跑 effect、不重取数据 |

### 12.2 三层架构（本仓库实现）

```
[按钮] 点一下
  ↓  lib/page-refresh-data.ts  refreshPageData()
     · queryClient.invalidateQueries()   重取 React Query 缓存
     · dataVersion += 1                  静态 JSON 的缓存穿透号
  ↓  成功才 notifyPageRefreshed()
  ↓  lib/page-refresh.ts  版本号 +1（useSyncExternalStore）
  ↓  App.tsx  <RefreshableRoutes key={v}>  key 变化 = 当前路由树卸载重挂
  ↓  页面重新读数据（标签栏 / 侧栏 / 滚动 / 主题 全保留）
```

### 12.3 文件清单

| 文件 | 职责 |
|---|---|
| `src/lib/page-refresh.ts` | 刷新总线：`subscribePageRefresh` / `notifyPageRefreshed` / `usePageRefreshVersion` / `usePageRefreshed`（零依赖，无 JSX） |
| `src/lib/page-refresh-data.ts` | `refreshPageData()` 唯一入口；`getDataVersion()` 缓存穿透号 |
| `src/lib/query-client.ts` | QueryClient 单例（抽出来给 lib 用，App 也 import 它） |
| `src/App.tsx` | `RefreshableRoutes`：`<React.Fragment key={v}>`，**只包业务路由树，不包 `/login`** |
| `src/components/tabs/TabBar.tsx` | 栏尾常驻按钮（四态）+ 右键菜单复用同一 `doRefresh` |
| `scripts/verify_refresh_20261028.mjs` | 19 项验收 |

### 12.4 四态（视觉即反馈，不等 toast）

| 状态 | 图标 | 颜色 | 其它 |
|---|---|---|---|
| `idle` | 静止 | 灰 `muted-foreground` | 待点 |
| `running` | 转圈 `animate-spin` | 蓝 `text-primary` | `disabled` + `cursor-progress` |
| `ok` | 静止 | 绿 `text-success` | 保留 1.2s |
| `fail` | 静止 | 红 `text-destructive` | 保留 1.2s |

`data-testid="tabbar-refresh"` + `data-state={四态}` —— 验收脚本据此断言，不靠截图肉眼。

### 12.5 五个必须做的细节（都是实测踩出来的）

1. **在途去重必须用 `useRef`，不能用 `state`** —— state 是异步的，连点时闭包里读到的还是 `"idle"`，
   用 state 守卫挡不住连点（实测连点三下打了三份请求）。
2. **给转圈一个最短展示时长（420ms）** —— 本地静态数据几乎瞬时返回，`running` 一闪而过，
   看起来就是"点了没反应"；规范验收项也要求 `running` 可被观测到。
3. **`hover` 只变色底，不 hover 变字色** —— 写成 `hover:text-accent-foreground` 会把
   `running/ok/fail` 三态颜色盖掉；用户点完鼠标还停在按钮上，就看不到"变蓝 / 变绿"了。
4. **广播必须在取数成功之后** —— 点了就广播 = 页面重挂但数据是旧的，比不刷新更让人困惑。
5. **静态 JSON 要带缓存穿透号** —— 不加 `?v=版本`，第二次 `fetch` 直接吃 HTTP 缓存，数据其实没重取。

### 12.6 验收（19 项，`ALL PASS`）

```bash
node scripts/verify_refresh_20261028.mjs
```

覆盖：按钮常驻/位置/高度 · 四态切换 · 转圈动画名含 `spin` · `cursor:progress` ·
三态颜色实测 · 1.2s 回 idle · 真的重取数据（网络请求增加）· 连点只触发一次 ·
右键菜单走同一动作 · 不是 `location.reload`（`window` 标记未清）· 0 pageerror。

> ⚠️ 期望值不要写死 `+2`：dev 下 `<StrictMode>` 会把 effect 跑两遍，一次刷新实测 `+4`。
> 正确做法是先量一次「刷新增量」当基线，连点/右键再跟基线比。

### 12.7 什么时候用 `usePageRefreshed` 而不是重挂

默认**所有页都靠重挂**（简单、一致）。只有「绝对不能重挂」的页才用订阅：
图表/画布内部有状态（缩放、播放进度、滚动锚点），重挂会丢。

⚠️ 但**别既订阅又让它重挂** —— 本仓库实测：给 `/plan-flow` 同时加 `usePageRefreshed`
会跟重挂叠加，同一次刷新打两遍请求（`plan_exports` +4 而非 +2）。订阅是"替代重挂"，不是"叠加"。

## 十三、弹窗也要「白框」（Dialog surface，2026-10-29）

### 13.1 问题

页面层已经做到「画布底 → 白框 → 框内容」，但**弹窗没跟上**：
`DialogContent` 本身就是 `bg-card` 白底，正文（表单字段 / 详情 dl）直接铺上去 ——
进弹窗等于进了一张白纸里，没有任何层次，字段是"飘在白底上"的。
维护者原话：「弹出的新建窗口你没有加那个白框……相当于把外面整个这个页面层做一个包装」。

### 13.2 方案：把弹窗当「一个小页面」

| 层 | 类 | light | dark |
|---|---|---|---|
| 外壳（画布底） | `bg-background` | `#F3F4F7` | `rgb(9,9,11)` |
| 正文白框 | `bg-card` + `border border-strong` + `shadow-surface` | `#FFFFFF` | `rgb(21,21,25)` |
| 描边 | `border-strong` | `#D1D4DC` | `rgb(55,55,62)` |
| 浮层投影 | `shadow-overlay` | 保持（弹窗仍需 elevation） | 同 |

层次与页面**完全同构**：弹窗外壳 = 画布，弹窗正文 = 白框。
暗色下框比壳**更亮**、亮色下框比壳**更白**，两种主题关系一致，不靠色相区分。

### 13.3 只开一个开关

```tsx
<DialogContent surface="canvas">   {/* 外壳降为画布底 */}
  <DialogHeader>…</DialogHeader>
  <DialogBody>                      {/* 自动套白框，无需额外 prop */}
    …
  </DialogBody>
  <DialogFooter>…</DialogFooter>
</DialogContent>
```

实现用的是 **React context**（`DialogSurfaceContext`），不是给 `DialogBody` 再开一个 prop。
原因：开关只能有一个 —— 「外壳已经是灰的、正文却没框」这种半吊子状态，从 API 上就构造不出来。

`surface` 默认 `"card"`：轻浮层（删除确认这种一两行字的）保持原样，套框反而累赘。

### 13.4 落地范围

| 弹窗 | surface | 理由 |
|---|---|---|
| `ProductDialog`（新建 / 编辑） | `canvas` | 有实体的表单，最需要框 |
| `DetailDialog`（详情，8 个字段的 dl） | `canvas` | 同上 |
| `DeleteConfirmDialog`（删除确认） | `card`（默认） | 一句话 + 两个按钮，套框是浪费 |

### 13.5 踩坑

19. **白框套白框 = 看不见** —— 弹窗本来是白的，直接在里面再加一层白框，只有描边、没有层次。
    必须先**把外壳降为画布底**（`surface="canvas"`），白框才成立。这与踩坑 14（画布页给画布加底色）是同一个病的两个方向：
    层面之间必须**有且只有一处**色差。
20. **弹窗的分界线也要 `border-strong`** —— `DialogHeader` 的 `border-b`、`DialogFooter` 的 `border-t`、
    `DialogContent` 的外描边，原先都是默认 `border`（`#E2E5EC`）。外壳降灰后，
    默认描边与画布底色几乎同值，分界等于消失 → 统一升 `border-strong`。

## 十四、顶栏面包屑（替换已删除的「通用查询」框，2026-10-29）

### 14.1 为什么换掉搜索框

顶栏左区原来是一个 `⌘K` 搜索框，但**从未接线**（无 onChange / 无键盘监听 / 无结果面板），
2026-10-29 维护者定：「没用就取消掉」。删掉之后左区全空，观感右重左空，于是改成面包屑。

### 14.2 为什么是面包屑（而不是别的填充物）

| 现有导航 | 缺什么 |
|---|---|
| 左侧导航 | 只高亮**当前项**，看不出层级（页面案例 → 列表页 → 详情 是三层） |
| 多窗口标签栏 | 只显示**当前页名**，标签平铺、没有父子，回不去上一级 |
| 顶栏 | 位置本来就有，`h-14` 已经占了高度，不新增任何占位 |

所以面包屑补的正是这两处盲区：**层级可见 + 上级可点**。

### 14.3 层级来源（不另建映射表）

| 层 | 来源 | 例 |
|---|---|---|
| 一级 | 固定「案例索引」→ `/` | 给一个随时回得去的锚点 |
| 二级 | `NAV_GROUPS[].label`（与侧栏同一份） | 页面案例 / 表格 / 查询 / 组件 / 布局区块 |
| 三级 | `NAV_GROUPS[].items[]`（与侧栏同一份） | 列表页 · 页面式 CRUD |
| 四级 | 路由剩余段 | `new` → 新建 / `edit` → 编辑 / `recipe` → 业务配方表单 / 单段 id → 详情 |
| 特例 | `/menu/*` 走 `MENU_LEAVES` | 多级菜单 / 日报 |

**★ 弹窗不算一层** —— 面包屑只表达**页面**层级。新建/编辑/运行弹窗是页内浮层，
不改 URL，也就不该改面包屑（维护者明确：「弹出框就不用了吧」）。

### 14.4 实测（1440 视口）

| 路由 | 面包屑 |
|---|---|
| `/` | 案例索引 |
| `/list` | 案例索引 / 页面案例 / 列表页 · 弹窗式 CRUD |
| `/list-page/new` | 案例索引 / 页面案例 / 列表页 · 页面式 CRUD / 新建 |
| `/list-page/p_001` | 案例索引 / 页面案例 / 列表页 · 页面式 CRUD / 详情 |
| `/list-page/p_001/edit` | 案例索引 / 页面案例 / 列表页 · 页面式 CRUD / 编辑 |
| `/form/recipe` | 案例索引 / 页面案例 / 表单页 / 业务配方表单 |
| `/menu/reports/daily` | 案例索引 / 多级菜单 / 日报 |

- 只有**最后一级**是纯文本（`aria-current="page"` + `font-medium text-foreground`），其余可点；
- 中间级悬浮 `hover:bg-accent`，与侧栏悬浮态同一语言；
- `< 768px` 隐藏（`hidden md:flex`）—— 窄屏顶栏只留品牌 + 操作，面包屑让位；
- 无截断：最长一级实测 `容器 924px` 内不换行不截断；真超长时 `truncate` 兜底。

### 14.5 踩坑

21. **不要给面包屑建第二份路由映射** —— 层级全部从 `NAV_GROUPS` / `MENU_LEAVES` 现算，
    否则侧栏改名后两处必不一致（单一级事实源原则）。
22. **子页要用「最长前缀命中」找父级**，不能按段数硬套：`/list-page/:id/edit` 与 `/form/recipe`
    层级深度不同，写死 2 段/3 段都会错。
23. **根路径不要输出「开始 / 案例索引」** —— 分组名在首页毫无意义，直接只留「案例索引」。
