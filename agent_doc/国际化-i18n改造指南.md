## 二、架构（先看懂这四件事）

### 1. 词条文件只有两个

```
src/i18n/locales/zh-CN.ts     ← 简体中文（默认语言）
src/i18n/locales/en-US.ts     ← 美式英文
src/i18n/index.ts             ← 初始化 + changeLocale() + 持久化
```

语言选择存在 `localStorage["shardkit.locale"]`（**不是** `i18nextLng`），默认 `zh-CN`。

### 2. 组件里只有一种写法

```tsx
import { useTranslation } from "react-i18next";

export function Foo() {
  const { t } = useTranslation();
  return <Button>{t("crud.export")}</Button>;
}
```

带变量用插值：

```tsx
t("crud.total", { count: total })      // zh: "共 {{count}} 条"  en: "Total {{count}}"
```

复数（英文需要 `_one` / `_other`）：

```tsx
t("crud.items", { count: n })          // en: items_one="item" / items_other="items"
```

### 3. 现有命名空间（往里加，不要另起新体系）

| 命名空间 | 管什么 |
|---|---|
| `app` `common` `header` `nav` `tab` `tabMenu` | 壳层（原有） |
| `menu` | 多级菜单树 + `/menu` 页 |
| `field` | 字段标签 / 表头（跨页面复用） |
| `crud` | 列表页增删改查通用词 |
| `query` | 查询页词 |
| `pagination` | 分页基元 |
| `productForm` | 产品表单 + 校验文案 |

### 4. 想做完整多语言（不止中英）

`src/i18n/index.ts` 里的 `SUPPORTED_LOCALES` 加一项 + 建一个 `locales/xx-XX.ts`，
其余不用改（顶栏语言切换是遍历这个数组生成的）。
**注意**：`resolveTabMeta(path, lang, t)` 的 `lang.startsWith("en")` 判断需要同步改，
否则新语言的标签页标题会回落中文。

## 三、五条铁律（都是踩出来的，别重犯）

### ① 往词条文件里插新块，锚点必须用命名空间级

```python
# ❌ 错：'    help: ' 在 header / nav 里都有 → 词条被插进错误的命名空间
# ✅ 对：
s.replace("  menu: {", NEW_BLOCK + "  menu: {", 1)
```

**我当时用键名当锚点，14 条词条插进了 `header` 命名空间，页面直接渲染出字面量 `menu.demoIntro`——tsc 一个错都不报。**
插完必须跑一次「正文里是否出现 `xxx.yyy` 字样」的正则校验。

### ② 参与逻辑比较的值，不是文案

```ts
export const CATEGORY_ALL = "全部类目";     // 筛选时 category === CATEGORY_ALL
```

**翻译它，筛选直接失效。** 正确做法：值不动，只在渲染时换显示。

```tsx
{c === CATEGORY_ALL ? t("crud.allCategories") : c}
```

### ③ 组件的形参默认值里调不了 `t`

```tsx
// ❌ 形参在 hook 之前求值
function DatePicker({ placeholder = t("ui.pickDate") }) {}

// ✅ 去掉默认，组件内兜底
function DatePicker({ placeholder }) {
  const { t } = useTranslation();
  const ph = placeholder ?? t("ui.pickDate");
}
```

**15 个 UI 基元都是这个坑**（`date-picker` / `calendar` / `time-picker` / `transfer` / `cascader` /
`tree-select` / `combobox` / `input-tag` / `empty-state` / `waterfall` / `rich-text-editor` …）。
这是「改代码结构」，不是「加个 `t()`」，要逐个组件验。

### ④ 这些中文是**故意留的**，别删

| 位置 | 为什么 |
|---|---|
| `mock/*.ts`、`*/mock.ts`、`productStore.ts` 的枚举值 | 演示数据 / 业务枚举（在售 active、消费电子、Amazon…） |
| `shell.tsx` / `tab-meta.ts` / `App.tsx` 里的 `L("中文","key")` | **中文兜底**：没传 `t` 时（测试、SSR）用中文，不用英文 |
| `lib/cases.ts` 的 `title` / `desc` | 与 `titleEn` / `descEn` **成对**存在，已有 `caseTitle(c, lang)` 选择器 |
| `status-badge.tsx` 的 `MAP` | 状态标签映射，**建议改成 key 而不是删** |

### ⑤ 案例页翻完可复制性会下降

`<TableHead>名称</TableHead>` 变成 `<TableHead>{t("field.name")}</TableHead>` 之后，
别人复制这个分片走，还得连带复制词条。**这是已知代价**，接受它再翻。

## 五、建议的动手顺序

1. **UI 基元先做**（`src/components/ui/`，约 106 处）
   基元被全站共用，先做它，后面页面里很多文案会自动跟着变。
   但要先解决第三条铁律（形参默认值）。
2. **`lib/registry.ts`**（17 处）
   组件注册表的分类与状态名。
3. **单页单个做**，一次一个文件，做完立刻 `tsc -b`。

不要一次改 10 个文件——出错了很难定位是哪个文件破的。

## 六、验收（每次改完必跑）

```bash
npx tsc -b                                    # 必须退出码 0
node scripts/check-ui-rules.mjs               # 四项计数不得上涨
node scripts/verify_surfaces.mjs              # ALL PASS
node scripts/verify_content_frame_20261028.mjs # 26 路由 + 0 pageerror
```

手动验收（切语言后逐页看）：

```js
// 浏览器控制台
localStorage.setItem("shardkit.locale", "en-US"); location.reload();
```

**特别注意**：切换语言后，**已经打开的标签页标题不会自动更新**（标题在开标签时快照）。
验证时要么重开标签，要么刷新页面。

## 八、想加自己的语言（比如日语 / 繁体）

1. 复制 `src/i18n/locales/en-US.ts` → `ja-JP.ts`，整份翻掉（它是当前最全的一份）。
2. `src/i18n/index.ts`：
   - import 新文件
   - `SUPPORTED_LOCALES` 数组加 `{ key: "ja-JP", label: "日本語" }`
   - `resources` 里加 `"ja-JP": { translation: jaJP }`
   - `getStoredLocale()` 的合法性判断加新 key
   - `applyHtmlLang` 不用改
3. 顶栏语言切换菜单会自动多一项（它是遍历 `SUPPORTED_LOCALES` 生成的）。
4. 跑第六节的四条验收命令。

**不要**为了加语言去改任何组件的写法——如果发现某处必须改代码才能翻，说明那里还没接好，按第七节的方式先接进词条。
