# 图标撞图检测（批量 logo / 头像 / 图标查重）

> 工具：`scripts/detect_collision.py`｜建立：2026-10-20｜整理归档：2026-10-21
> 适用：一批图标（logo / 头像 / 功能图标）生成或交付前的自查
> 一句话：**查的不是「全库唯一」，而是「同一屏里分不分得清」。**

---

## 1. 什么时候用

- 批量生成图标（AI 生成 logo / 头像 / 功能图标）之后；
- 引入第三方图标集、或多批素材合并之后；
- 做列表页 / 卡片墙 / 头像组之前（这些地方图标是**混排**的）。

**核心症状**：单看每张都合格，混排到一个列表里却分不清谁是谁。

---

## 2. 判定标准（三条，任一命中 = bad）

| 判据 | 阈值 | 说明 |
|---|---|---|
| md5 相同 | — | 直接照抄 |
| **形状撞车** | 灰度 MAE **< 12** | 几乎同一个形 |
| **同形近色** | MAE **< 20** 且 主色距 **< 60** | 换个颜色想蒙过去，不算 |

分级：

| 情况 | 结论 |
|---|---|
| `MAE ≥ 20` | ✅ ok |
| `12 ≤ MAE < 20` 且 色距 `≥ 60` | ⚠️ warn：形状像但颜色迥异，人眼分得清，可接受 |
| `MAE < 12` | ❌ bad：形状撞车 |
| `MAE < 20` 且 色距 `< 60` | ❌ bad：同形近色 |

其中：

- **MAE** = 两张 64×64 灰度缩略图的平均绝对误差（0 = 完全相同）
- **色距** = 主色 RGB 欧氏距离（0 = 同色，最大约 441）

### 为什么两个维度都要看

| 只看灰度 | 只看颜色 |
|---|---|
| 「红色加号」和「蓝色加号」被判撞车（形状确实一样，判得对） | 「同一个调色盘换色」被判合格（但它就是撞车） |

结论：**形状像 + 颜色像 = 真撞；形状像 + 颜色迥异 = 弱撞，可接受。**

---

## 3. 工具用法

```bash
# 一个目录（或一组文件）= 同一屏，全交叉比对
python3 scripts/detect_collision.py ./icons

# 多个屏分开算（各自全交叉，屏与屏之间不比）
python3 scripts/detect_collision.py \
  --scope "列表页=./a.png,./b.png" \
  --scope "详情页=./c.png,./d.png"

# 调阈值
python3 scripts/detect_collision.py ./icons --mae-hard 10 --mae-soft 18 --color 50

# 机器可读（接 CI）
python3 scripts/detect_collision.py ./icons --json
```

依赖：`numpy` + `Pillow`（`pip install numpy pillow`）。

### 输出示例

```
检测 3 张图片，1 个作用域：
  · default：3 张

判定        MAE     色距  说明 · 两张图
------------------------------------------------------------------------------------------------
BAD      0.00      0  完全相同（md5 一致） · t-plus.png × t-plus2.png

★ 优先改这几张（卷入 bad 次数降序，改一张能消掉多条）：
   1 次  /tmp/icon_test/t-plus.png

结果：bad=1  warn=0
SOME FAIL
```

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 无 bad（warn 允许），末行打印 `ALL PASS` |
| `1` | 存在 bad，末行打印 `SOME FAIL` |
| `2` | 用法错误 / 无可读图片 |

> 接 CI 时只看退出码即可；要详情用 `--json`。

### 参数一览

| 参数 | 默认 | 用途 |
|---|---|---|
| `--mae-hard` | 12 | 形状撞车阈值（调小 = 更宽松） |
| `--mae-soft` | 20 | 形状相似阈值（进入 warn/bad 的分界） |
| `--color` | 60 | 主色距离阈值 |
| `--thumb` | 64 | 比对缩略边长（**按实际显示尺寸设**，见 §4） |
| `--ink` | 235 | 「非白即墨」判定：RGB 最小值小于此值算墨 |
| `--top` | 10 | 「先改哪张」榜单条数 |

---

## 4. 阈值怎么定（重要）

**`--thumb` 要跟界面里的实际显示尺寸一致。**

图标在列表里可能只显示 32~64px，而素材是 512/1024px。判据必须在**显示尺寸**上算——
因为「1024px 看得出差别、64px 糊成一团」正是要抓的那种问题。

> 默认 64 是我们实测的列表头像尺寸。你的界面若用 40px，就传 `--thumb 40`。

**首次接入建议**：先跑一遍全量，人工看 bad 列表里有没有「明显不该判的」。
若误判多 → 说明作用域没收窄（见 §5），不要急着调阈值。
若漏判（肉眼能看出撞但没报）→ 把 `--mae-hard` 从 12 提到 14~16。

---

## 5. ★★ 作用域：必须「同一屏」，不是「全库」

**成对比较的范围决定结论对不对。**

- ✅ **同一列表 / 同一屏内的对象必须全交叉**（项目 + 任务 + 头像混排 → 三类互相两两比）
- ❌ **不要跨批次全局套用** —— 会把「有意的设计」全判成撞车

实测反例：149 张全交叉 → 105 对 bad，**没有一对是真缺陷**：

| 组合 | 对数 | 真相 |
|---|---:|---|
| avatar × avatar | 54 | 家族语言：一个项目 5 个角色共用图形、靠**色相**区分。灰度比对看不见色相 → 一律判死 |
| avatar × project | 10 | 项目 logo 与该项目 PM 头像 **md5 完全相同**，本来同源 |
| avatar × task | 41 | task 与其对应 worker 头像同形（`book_write_section` ↔ `book_writer`），角色对应，有意为之 |

**所以：判「撞车」看的是「同一个人在同一界面上能不能分清」，不是「全库图是否唯一」。**

工具里的 `--scope` 就是干这个的：一个 scope = 一个屏。

---

## 6. 修法：优先改外轮廓，别改颜色

同一家族的多个图标常共用同一个外框，**外框占 90% 墨量、内部符号只占 5~8%**。
缩到 64px，内部符号的差别只剩两三行像素——而界面里就是这个尺寸。

- ✅ 换**外轮廓**（方形 → 圆形 / 缺角 / 异形边框）
- ❌ 不要改颜色：同族统一色是**设计意图**（靠色相区分角色），改色会破坏家族语言
- ⚠️ 「加号 vs 减号」这类语义对应：1024px 看得见，64px 就糊了 → 必须换外框

### 先改哪张最省事

工具会输出「卷入 bad 次数降序」榜单。**先改顶部几张，一轮能消掉大半。**

> 实测：18 对撞车，改 4 张（各卷入 3 次）就解决了 12 对。

---

## 7. 排查顺序（碰到类似问题时照着走）

1. 是不是只查了同类型？→ 补跨类型
2. 是不是只看灰度？→ 补色相维度
3. 是不是只改内部符号？→ 改成换外轮廓
4. 是不是把跨批次的有意设计判成撞车？→ 收窄作用域到同一屏
5. 是不是透明底没合成白底？→ 工具已内置处理（v1.1）

---

## 8. 局限（不适用场景）

| 场景 | 说明 |
|---|---|
| **照片 / 插画 / 复杂渐变** | 灰度 MAE 对这种素材没有判别力，会大面积误报。只适合**线性/实心风格图标** |
| **SVG 源文件** | 不支持直接读。先栅格化：`npx sharp-cli -i a.svg -o a.png resize 256` 或 `cairosvg a.svg -o a.png -s 2` |
| **单色图标集**（全是同色） | 色距恒为 0 → 退化为只看形状。此时判据等同于「形状撞车」，把 `--mae-hard` 收紧到 10 更稳 |
| **主色占比极小的图标** | 主色取「非白像素众数簇均值」，若图标 95% 是灰线 + 一点彩色点缀，主色会偏灰。必要时先统一上色再测 |
| **动画 / 动态图标** | 取首帧，不评估动画差异 |

---

## 9. 成功判据

- `python3 scripts/detect_collision.py <目标目录>` **退出码 = 0**（bad = 0）；
- 有残留 warn 的，逐条写明「为什么可接受」（形状像但色差大、且不在同一屏）；
- 达不到就说明原因，**不要报「已完成」**。
